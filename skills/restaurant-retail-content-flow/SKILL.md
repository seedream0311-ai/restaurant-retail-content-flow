# 餐飲零售內容匯流

這裡的「數位匯流」指：以一篇長篇部落格文章為共同內容來源，轉寫為 Facebook、Instagram、Threads、LINE OA 文案與相關圖像，再延伸為適合 Threads、YouTube Shorts、TikTok 的短影音拍攝腳本。保留同一組商家事實與 CTA，依各媒體的閱讀或觀看情境重寫。預設使用繁體中文。

本 Skill 可產出內容，並依請求執行網站後台與社群的發布、儲存草稿或排程。實際執行依賴當前環境的可用工具、帳號權限與素材；寫入此流程不代表已連接或測試任何網站或社群帳號。成片製作及成效追蹤需另有請求，不把腳本當成影片，也不把發布描述為已產生業績。

## 選擇工作範圍

- 只要文章、文案、素材或操作說明：完成內容與說明，不自行登入、建立遠端草稿或發布。
- 要發布、存草稿或排程，或上下文已包含發布的全流程請求：沿用既有授權與已設定偏好。目標和內容已知時，完成必要檢查後直接執行指定動作，不再要求相同許可、固定口令或人工填入審核代碼。
- 需要執行目的地操作時，讀取 [網站與社群發布流程](references/publishing.md)。依請求只處理指定渠道，不能把「全平台內容包」自行解讀成向所有帳號發布。

## 接收資料

接受以下任一輸入，沿用使用者已提供的資料，不要求重填表單：

- **商家簡報**：業種／商家名稱、服務或商品、目標客群、想解決的情境、可確認的特色、希望讀者採取的行動。語氣、發布渠道、圖片素材及禁用詞有提供才採用。
- **既有長文**：文章全文加上必要的商家事實或 CTA 修正。先抽取主旨與事實，再整理成可作共同來源的部落格稿；保留原意，不為了「重寫」擅自變動資訊。

只有會實質改變商家身分、主要商品、核心訊息或 CTA，且無法從上下文合理推定的缺漏，才集中問一次。內容草稿缺少網址時先用「［請填 LINE OA 連結］」等明確佔位符；缺少價格、時間、地址、優惠與證據時省略相關敘述，不用提問拖住其餘產出。發布所需的目標、帳號、登入或必要媒體缺漏則依發布流程處理，不能把佔位符送到公開內容。對於課堂或原型，使用合理的版型與語氣預設，清楚列為「暫定」。

若使用者要求虛構教學案例，標示其虛構身分；不要把虛構資訊包裝成真實商家資料。不因需要示範而自行補上價格、優惠、日期、營養／健康效果、顧客數、地址或可用連結。

## 共同事實表

動筆前建立精簡事實表，輸出時保留它，讓各渠道可逐一回查：

| 欄位 | 填寫方式 |
|---|---|
| 主題與客群 | 一個共同主題；明確對象與使用情境 |
| 已知事實 | 逐項列出使用者提供的商家／商品資訊，必要時加 F1、F2 等編號 |
| 來源與狀態 | 區分「使用者提供」「原文主張，未驗證」「虛構教學設定」 |
| 不得推定 | 缺少依據的價格、優惠、效能、數量、時間與其他限制 |
| 共同行動 | 一個主要 CTA；缺少目的地則使用可辨識的佔位符 |
| 暫定設計 | 語氣、篇幅、畫面比例與影片長度；註明是可調整的製作選擇 |

以此表作為所有輸出的唯一商家事實來源。可增加生活情境、提問與創意表達，但不要因此新增商品承諾。原文中的未驗證數字、健康效果或保證性主張先標記或省略，不把原文當作已獨立查證；需要查證時依使用者要求處理。使用者指定不研究外部資料時，僅使用所給資訊並明示資料界線。

## 產出流程

### 1. 共同文章

由商家簡報撰寫原創部落格草稿；若有長文，整理出保留原意的共同來源稿。用一個讀者情境帶出核心觀點，提供可理解的內容，結尾接共同 CTA。先完成文章，再由文章提取重點轉寫渠道，避免四篇各自發想而互相矛盾。

預設教學稿為約 500–800 個中文字，不含標題；這是課堂可完成的暫定篇幅，使用者可指定較長文章。提供標題、段落與 CTA，避免填充式 SEO 文字、無依據成效及虛構見證。

### 2. 四平台完整文案

每份文案須可單獨閱讀、完整收尾；保留共同事實與 CTA，但從同一來源重新組織切入點，不能只縮短或換行。篇幅是暫定教學設計，並非平台當前限制。

| 渠道 | 改寫方式 | 暫定篇幅 |
|---|---|---|
| Facebook | 情境開場、解釋讀者困擾、帶出一個做法，結尾邀請行動或討論 | 約 150–250 字 |
| Instagram | 配合主視覺的一句鉤子、短段落與易掃讀重點；CTA 指向使用者實際提供的連結位置，未知則使用佔位符 | 約 80–150 字；少量相關標籤可選 |
| Threads | 單一觀察或問題，語氣像自然對話；讓人願意回覆，再柔和接 CTA | 約 60–120 字 |
| LINE OA | 以既有好友的閱讀情境直述重點，提供一個明確行動；不假設已收到任何訊息或已確認庫存 | 約 60–120 字 |

LINE OA 的回覆按鈕、關鍵字、自動回應及 Instagram 的個人檔案連結，只有確知已設定才寫成可用功能。使用「可在此放置……」清楚區分配置建議與既有能力。

### 3. 圖像素材

先定義一張可支援多渠道的主視覺：主體、場景、情緒、構圖與文案留白。提供可直接使用的圖像生成提示詞，並附繁體中文用途說明、替代文字及可延伸的裁切建議。

- 課堂暫定：文章橫幅 16:9、社群主視覺 1:1、短影音構圖 9:16。這些是構圖選擇，不代表已驗證的渠道規範。
- 把商家已知事實與視覺想像分開。虛構菜色或產品畫面標為「教學示意圖，非實際商品照片」；真實商品則優先使用使用者提供且有權使用的素材。不要擅自畫出商標、認證或不實商品效果。
- 使用者要求圖像或整包素材，且圖像工具可呼叫時，實際生成至少一張並檢視結果，依工具的使用規範執行。若有相應的圖像工具 Skill，僅為該工具操作按需讀取，內容工作流程不依賴其他個人 Skill。
- 避免將精確中文字、價格或網址交給生成模型；必要文字用後製編排建議標示。保留不被裁切的重要主體與文字留白。
- 列出 **實際產生的檔案／圖片** 與 **尚未生成的提示詞／構圖建議**。工具不可用或失敗時交付提示詞並說明狀態，不聲稱圖片已生成，也不為同一失敗無限重試。

### 4. 可拍攝的短影音腳本

以同一文章的一個重點，寫出 30–45 秒可由商家現有人手與手機拍攝的腳本。預設 40 秒、直式 9:16，均為暫定設計。用「前段鉤子 → 情境與做法 → 單一 CTA」安排節奏，不加入未提供的見證、價格、優惠或實證效果。

提供下列表格，每鏡有清楚的起訖時間，時間連續且加總落在 30–45 秒：

| 時間 | 鏡頭與拍法 | 口播 | 螢幕字幕 | 所需素材／道具 |
|---|---|---|---|---|

口播與字幕分開寫；字幕簡短且不與口播衝突。依自然語速估計後逐句試讀，保留停頓與 CTA 閱讀時間；寫不下時先減字，不靠加速塞入。列出總秒數、拍攝清單、主要 CTA 與尚缺素材。

用同一次拍攝的素材支援三個渠道，分別交付 **開場文字／首畫面改法** 與 **完整短貼文 caption**，不要求重拍三支影片：Threads video 可用一個可回覆的問題開場；YouTube Shorts 讓首畫面與標題能獨立說清楚主題；TikTok 可用生活化動作或 POV 開場。改編保留原腳本事實。這些是創作選擇，不宣稱演算法效果或最新格式規則。不以「改編備註」暗示已製作成片或已分發。

### 5. 網站與社群操作（依請求）

使用 [發布流程](references/publishing.md) 核對目的地與帳號、整理網站文章格式與實際媒體、執行指定的發布／草稿／排程，再逐一讀回結果。涵蓋網站後台、Facebook、Instagram、Threads、LINE OA；Threads 影片、YouTube Shorts、TikTok 的影片發布須已有真正完成的影片。執行受阻時保留已完成內容及成功目標，明確列出缺少的條件。

## 交付與檢查

依需求交付 Markdown 或可編修檔案，內容包含：共同事實表、共同文章、四平台完整文案、圖像及生成狀態、分鏡腳本、渠道改編備註。只要求部分輸出時照其範圍交付，不強迫整包。

完成前逐一核對：

- 各渠道的商家、商品、對象、CTA 是否一致；有無從缺漏處自行補出事實。
- 四平台是否有各自的切入點與閱讀結構；Facebook、Instagram、Threads、LINE OA 是否都已交付。
- 圖像的真實／示意身分、實際生成狀態與檔案位置是否清楚。
- 影片時間是否連續、總長是否正確、口播是否讀得完、鏡頭是否拍得出來；Threads、YouTube Shorts、TikTok 是否都有改編備註。
- 暫定長度與比例是否誤寫成平台規定；草稿、已生成素材與未實作功能是否分清楚。
- 有執行目的地操作時，是否取得實際文章／貼文／訊息 ID、網址或平台狀態；排程時間與時區、部分失敗及待核實結果是否如實記錄。

最後簡述已完成的可用產物、實際執行結果及仍缺的條件。只完成使用者要求的範圍，不自行追加研究、渠道、發布或週期性自動化。

## 最小呼叫例

> 使用 $restaurant-retail-content-flow。以下是虛構教學案例：午間食堂提供平日外帶午餐，對象是附近上班族，希望讀者透過 LINE OA 詢問今日菜單。沒有提供價格、優惠、地址或實際連結，請勿補造；不搜尋網路。請只產出完整內容包，不發布或建立遠端草稿；圖片標示為教學示意，所有篇幅與比例採暫定教學設定。

零售可改填「一家文具選物店，客群是想整理工作桌的上班族，已知品項是筆記本與收納用品，CTA 是透過 LINE OA 詢問商品資訊」；不要把餐廳的菜單、菜色與午餐情境直接套入。

發布用法：使用者可指定「沿用這次確定的文章與媒體，發布到已指定的官網、Facebook 粉專與 Instagram 帳號；其餘渠道只產草稿」，或提供確切日期、時間與時區要求排程。從既有對話及可用工具解析目標，不將此示例當成發布授權。

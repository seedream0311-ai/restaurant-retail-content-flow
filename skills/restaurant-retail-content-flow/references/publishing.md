# 網站與社群發布流程

只在請求包含目的地操作時讀取。這是可用工具的操作指引，不是已部署的跨平台連接器。沒有工具、帳號權限或必要素材時，不能聲稱支援已接通，也不能把準備好的 payload 當成發布完成。

## 解析目標與動作

先沿用對話中的授權、已設定偏好、來源文章與內容版本，再從可用工具讀取必要狀態。不要要求使用者重填已知資料。每個目標至少需能確定：

| 項目 | 所需資訊 |
|---|---|
| 網站 | 實際網站 URL、後台／CMS 類型、目的文章或欄位、操作帳號與權限 |
| 社群 | 平台、確切粉專／帳號／頻道、貼文或影片格式；LINE OA 另含訊息類型與收件範圍 |
| 內容 | 源文及各渠道定稿版本、實際圖片／影片、CTA 入口、需要沿用的文章或草稿 ID |
| 動作 | 每個目標要立即發布、存草稿或排程；未提及的渠道不自動加入 |
| 排程 | 確切日期、時間、時區，並核對平台顯示的換算結果；只有要求週期執行才建立 recurring automation |

使用者明確要求發布，或全流程請求的上下文已包含發布，且目標與內容已知時，這就是執行依據，不需要再問一次相同許可。生成或說明請求不提供發布授權。「傳到 LINE OA」若不足以判定是後台草稿、測試訊息或正式群發，僅澄清該差異；不擅自向全部好友群發。多帳號或多網站時，從名稱及穩定 ID 核對目標，不能猜選第一個。

若缺少必要的目標、帳號、登入、媒體、排程時間或權限，報告具體缺漏及受影響的目標，先完成不依賴它的內容工作與其他已授權目標。不用不明確的「需要審核」取代可描述的阻礙，也不把等待當作已取得答案。

## 選用工具與核對帳號

優先使用實際可用且已認證的連接器、API 或 CLI。先確認其提供的操作及目的地讀取能力；沒有適用的直接工具時，可使用可用瀏覽器控制操作網站或平台後台。依工具規範讀取介面，不虛構工具名稱、端點、成功回應或憑證。

在第一次寫入各目的地前，核對網站網域／CMS 與登入帳號，或粉專／帳號／頻道名稱及 ID，以及該帳號是否具有所需權限。沿用正確的登入狀態與既有授權；登入失效或權限不足時，只處理相應阻礙，不擅自切到另一個已登入帳號。

不綁定個人品牌、登入設定或其他個人 Skill，也不假設所有網站都是 WordPress。只有確認實際 CMS 為 WordPress 才選用當前可用的 WordPress 後台、REST API 或 CLI；其他 CMS 應確定其後台和支援的操作後再處理。不要為單次發布自行部署整合、安裝網站外掛、修改權限或設定憑證。

## 發布前整理與實際檢查

以共同事實表逐項檢查文章、文案、CTA 和實際媒體，修正無依據主張、渠道差異與素材不一致。記錄真實檢查發現、已修正項目及未解決問題；不虛構 `PASSED` 結果，也不要求固定批准字串。可自行處理的格式或文字問題直接修正；會改變關鍵事實或發布意圖的問題才向使用者釐清。

公開或排程內容不能保留待填網址、假菜色、虛構營業資訊或缺失媒體。若 CTA 必須有有效入口，就取得並核對實際網址或已設定功能；若不依賴連結，使用符合已知事實的純文字 CTA 即可。以使用者要求的可發布版本為準，不自行把課堂的午間食堂示例送到真實帳號。

圖片需為確實存在、可讀取且適用本次內容的檔案或媒體 URL；示意圖保留必要標示，不能當作真實商品照片。影片發布需讀取真正完成的影片檔或可存取媒體 URL，核對格式與內容；腳本、分鏡或生成提示詞不能替代影片。當前上傳要求以可用工具及後台實際限制為準，不能把課堂暫定比例／長度當成平台規定。

## 執行網站後台操作

1. 查閱指定文章或既有未發布草稿；有已知草稿 ID 時優先更新同一筆，避免重建。只有要求修改既有公開文章時才更新公開內容。
2. 依實際 CMS 將文章整理成支援的區塊、HTML 或編輯器內容，保留標題、段落、CTA。摘要、分類、特色圖、替代文字等欄位採既有偏好與目的地要求，不自行加入無關 SEO 或 RWD 規則。
3. 上傳或引用必要的真實媒體，讀回媒體 ID／URL 並確認可顯示；已有可用媒體時優先沿用。預覽內文與圖片，不能只貼上本機路徑而當作上傳完成。
4. 執行指定的存草稿、發布或排程操作。用讀回 API／後台文章狀態及實際 URL 驗證結果；發布後再查看公開頁面的內容、圖片與 CTA。草稿連結或預覽連結不是公開網址。
5. 若社群文案依賴此文章的公開網址，網站發布成功後才填入已驗證的實際網址。網站尚未公開時，保留該依賴並說明，不將草稿 URL 放進公開貼文；未依賴該網址的已授權渠道可繼續執行。

## 執行社群操作

保留各平台專屬改寫，依實際可用功能設定文案、媒體、目標和動作：

| 平台 | 執行要點與可驗證結果 |
|---|---|
| Facebook | 核對粉專、貼文格式、文字與媒體；以貼文 ID、實際 permalink 或後台草稿／排程狀態驗證 |
| Instagram | 核對帳號及貼文／影片格式、實際媒體和 caption；等待媒體處理完成，以貼文 ID／permalink 或後台狀態驗證 |
| Threads | 核對帳號、文字與附圖；若要求影片須有完成影片。讀回貼文 ID／實際網址及狀態 |
| LINE OA | 核對官方帳號、訊息型態、收件範圍、內容及立即／排程發送意圖；以平台發送紀錄、排程狀態或訊息／請求 ID 對應的執行狀態驗證。只有請求 ID 時記為已提交、待核實。平台接受請求不等於每位好友已收到或已讀，沒有公開網址時不虛構網址 |
| YouTube Shorts、TikTok | 僅在使用者指定影片發布且已有成片時操作。核對頻道／帳號、影片、標題或 caption、可見性與時間；驗證處理／發布狀態及實際網址，只有腳本時明確報告尚缺成片 |

草稿與排程不是各工具必然具備的功能。工具不支援所需操作時，使用適用的後台功能；仍不可用就報告受阻，不擅自改成立即發布或發送。排程成功須讀回正確時區及日期時間，不把上傳完成或處理中誤報為排程成功。

## 結果確認、部分失敗與重試

為每個目的地保留簡短執行紀錄：平台與帳號 ID、內容版本、要求的動作、既有或新建物件 ID、操作時間與時區、實際狀態、網址或後台證據、尚缺條件。不要記錄密碼或 token。

提交後遇到逾時、錯誤或回應不明，先透過回傳 ID、指定草稿、最近貼文／發送紀錄及時間與內容查詢是否已成功。API 有已支援的冪等鍵時，同一邏輯請求重試沿用同一鍵；不杜撰冪等能力。LINE 群發尤其不能因未收到成功訊息就再送一次。

部分成功時保留成功結果，不重新發布所有渠道，不為了整組一致而刪除成功貼文。只在確認失敗且已消除原因後重試受影響目標；遇同一原因持續失敗、結果仍無法確定或缺少外部條件時停止該目標，報告「待核實」或具體阻礙，不能盲目重送。

最後逐項區分「內容已準備」「草稿已儲存」「已排程」「處理中」「已發布／已發送」「失敗」「待核實」。提供真實取得的 URL、物件 ID 與狀態；未取得就寫未取得。填好編輯器、準備 payload、提交後尚未讀回，均不是已發布成功。
